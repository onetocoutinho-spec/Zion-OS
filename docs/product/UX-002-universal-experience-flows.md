# UX-002 — Universal Experience Flows

> O mapa comportamental da Zion. Hipótese testada: **existe uma única operação;
> os perfis diferem apenas no ponto de entrada.** Veredito: **VERDADEIRA, com
> uma fronteira declarada.**

## O ciclo operacional universal

```
CHEGADA → COMPLETUDE → PREPARAÇÃO → DECISÃO → PRESENÇA → EVOLUÇÃO
   ↑_______________________________________________________|
```

Mapeia 1:1 no Blueprint: Chegada+Completude = Catálogo Vivo · Preparação =
Vitrine · Decisão = Missões (transversal) · Presença = Publicação+Pulso ·
Evolução = Conversas+Combinados. Em 4 movimentos macro: **VERDADE → EXPRESSÃO
→ PRESENÇA → EVOLUÇÃO.** A frase irredutível: *a Zion transforma alegações de
verdade em presença comercial saudável — e aprende a cada volta.*

## A descoberta central

**O perfil de uma empresa é apenas onde ela está em relação à verdade do
produto.** Todas as portas de entrada (ERP, Excel, e-mail, API, XML,
importação, manual, PIM) produzem a mesma coisa — *uma alegação de verdade com
lacunas* — e convergem no mesmo ponto: verdade declarada com faltas honestas.
Dali em diante, a origem é irrelevante.

## Os 7 Experience Flows

| Flow | Cadeia (evento → percebe → prepara → missão → DECISÃO → executa → aprende → registra → termina) |
|---|---|
| **F1 Chegada** | catálogo chega → reconhece/deduplica/normaliza → completa com o que sabe → "340; 312 prontos" → *nenhuma* → integra → aprende formatos → Diário → prontos p/ completar |
| **F2 Completude** | faltas → separa quem sabe o quê → perguntas de 1 toque + msgs p/ fornecedor → "15 perguntas, 15 min" → **responder o irredutível** → grava → cada resposta vira memória → Diário → catálogo inteiro |
| **F3 Preparação** | verdade completa → expressões por canal → vitrine + etiquetas âmbar → "93 prontos" → **aprovar/ajustar/devolver** → incorpora em silêncio → aprende o gosto → Diário → lote aprovado |
| **F4 Decolagem** | lote aprovado → valida por canal → plano 3-primeiro → "publicar?" → **"continuo?"** → publica, traduz rejeições → aprende leis vivas → Diário → tudo no ar |
| **F5 Vigília** | o mundo muda → compara com o combinado → resolve/prepara → missão SÓ nos 4 motivos → **a exceção** → executa → aprende padrões → Diário → silêncio |
| **F6 Demanda** | comprador age → classifica urgência → rascunha com a verdade → "resposta pronta" → **aprovar/editar** (ou combinado: envia) → responde/encaminha → aprende o tom → Diário → atendido |
| **F7 Evolução** | percepção madura → junta histórico → formula o Combinado → Conversas → **conceder/agora não** → faz sozinha (com volta) → mede a si → Combinados+Diário → um peso a menos |

## Invariantes (idênticas para todos os perfis)

1. A ordem do ciclo · 2. A anatomia da missão (validada: 6 partes, inalterada;
enriquecida por **lote** e **Endereçado**) · 3. Honestidade sobre lacunas ·
4. Os 4 motivos · 5. Toda decisão deixa rastro e ensina · 6. Autonomia por
assunto, conquistada, reversível · 7. Indiferença à porta · 8. A pergunta
única: "o que importa agora?".

## Variáveis (parâmetros, jamais modelo novo)

Porta de entrada · completude inicial da verdade · **mapa de donos de decisão**
(agência: aprovar É do Cliente; executar, da agência — a missão ganha
Endereçado) · lote · lente de tenant · direção da verdade por porta (ERP-mestre
× Zion-mestre) · conjuntos de requisitos (importador). **Nenhuma exige etapa,
experiência ou anatomia nova.**

## Escala

1→10→100 lojas: lotes + lente. Agência: a fila vira **fila compartilhada por
equipe** (endereçamento + redistribuição — exatamente o desenho da constituição
do Operation Center). Global: tenants + requisitos + portas. O ciclo, intacto.

## Veredito

> **A Zion não é um software para um tipo de cliente. É um sistema operacional
> para operações comerciais.** A pergunta "esse fluxo é para fabricante ou
> seller?" não tem resposta porque não tem sentido.
> *Fronteira declarada:* governar a presença de **terceiros** (brand policing)
> é outro trabalho — fora deste modelo por decisão, não por esquecimento.
